# KirCloud Console · CrispAI

基于 [Haruka-Network/CrispAI](https://github.com/Haruka-Network/CrispAI) 的自部署扩展。
管理后台由 `frontend/`（Vite + React + HeroUI）构建，取代上游的预编译页面；
项目页分为基础设置、自动回复、智能回复、知识库、选项管理五个标签，全局模型配置在 `/settings/ai`。

Crisp 智能客服助手的自部署版：关键词自动回复、AI 回复（带知识库检索）、选项卡片、欢迎语，
以及把每个 Crisp 会话同步到 Telegram 话题群，客服直接在 Telegram 里回复。
同一个项目还可以同时接入 Chatwoot，两边共用提示词、关键词、选项卡片和知识库。

单用户、多项目。一个 `docker compose up` 起全套：

| 服务       | 说明                                                                     |
| ---------- | ------------------------------------------------------------------------ |
| `app`      | Bun + Hono。Webhook、BullMQ worker、管理后台 API，以及管理页面的静态文件 |
| `postgres` | `pgvector/pgvector`，知识库检索用 vector 扩展                            |
| `redis`    | BullMQ 队列                                                              |

## 部署

需要一个能被公网通过 **https** 访问的域名（Crisp 和 Telegram 的 Webhook 都要回调它）。

```bash
cp .env.example .env     # 按文件里的注释填写
docker compose up -d
```

然后用反向代理（Caddy / Nginx / Traefik 等）把域名指到 `127.0.0.1:3000`，打开
`https://你的域名/`，用 `ADMIN_USER` / `ADMIN_PASSWORD` 登录。数据库表在首次启动时自动创建。

### 登录与模型服务

1. 打开 `/login`，使用 `.env` 中已有的管理员账号密码登录。
2. 点击右上角机器人图标进入 **模型服务**（`/settings/ai`），这里的配置所有项目共用。
3. 填写 OpenAI 兼容 API 的 Base URL 和 API 密钥，点击「读取列表」从服务商 `/models` 选择对话模型，也可以直接输入模型名。
   使用 DeepSeek 时可填写 `https://api.deepseek.com`。
4. 点击「测试连接」验证当前表单；向量模式下会同时检查向量输出是否为 1536 维。
5. 点击「保存设置」。配置写入 PostgreSQL，新请求即时生效，无需重启容器。
6. 进入具体项目的「智能回复」，开启 AI 回复并保存。全局接口配置不会自动开启任何项目的 AI。

密钥只保存在服务器，读取接口不会返回它。密钥输入框留空会保留现有值；
测试连接使用当前表单，但不会保存，且会向所选服务商发送简短测试请求，可能产生少量费用。
在「知识库模式」中选择使用方式：

- **全文模式**：每次回复直接引用当前项目的最新资料，不调用 Embeddings，适合少量教程。
- **向量检索**：先用支持 Embeddings、输出 1536 维的模型检索相关段落，再交给对话模型回答，适合更大的知识库。
- **不使用知识库**：仅使用项目提示词与聊天历史。

每次引用的资料默认上限为 16000 字符，可设为 2000～64000。预算包含标题、分隔符和说明；
超出时只保留前面的资料，并明确标记省略。字符上限只限制知识库部分，不代表模型的 Token 上下文上限，
仍需为系统提示词、聊天历史与回复预留空间。全文每次都会发送资料给对话模型，输入较长会增加 Token 用量。
资料不写入会话历史，每次读取数据库，因此同步更新后下一次回复即使用最新内容。

首次迁移时，已配置向量模型的实例保留向量模式；没有向量模型的实例默认全文模式。

选择「向量检索」后，可单独填写向量 API 地址、密钥并读取其 `/models`；
向量地址留空时复用对话接口。不同服务商必须单独填写密钥，后端不会将对话密钥发送到另一家向量服务商。
已保存的向量密钥同样不会回显，留空保留。

资料条目和文档同步来源都在项目的「知识库」标签里。全文模式可直接保存、编辑条目，无需密钥或索引；
由文档同步维护的条目标记为「同步」，请在源站修改。
向量模式下，「知识库」标签显示已索引/待索引数量，「生成待索引」会依次处理；失败后已完成的条目会保留，再次点击可继续。
更换向量模型后点击「全部重新生成」。生成索引会将文档正文发送给配置的向量服务商，并产生相应 API 用量。
向量模式下，对话时自动检索当前项目最相关的 3 条资料并作为参考上下文传给对话模型。

同一页面的「文档自动同步」支持 V2Board 风格的 `knowledge/fetch` 接口：填写 API 地址、
Authorization 完整值和用户查看教程的地址，保存后可立即同步，或开启定时同步（15 分钟至 7 天）。
后台每分钟检查到期来源，读取目录及 `?id=...` 正文，以正文哈希比较变化。
全文模式下，同步后直接可用，不生成向量。向量模式下，只对新增或变化内容重新生成向量；
未变条目保留索引；撤下内容保留存档但退出知识库使用。
同步只管理带来源标识的条目，不改手动添加的知识库和项目设置。
源站共享账号访问区块、iframe、脚本和个人订阅模板不会写入检索正文。
接口访问失败时保留现有文档；向量接口失败时保留待处理条目，可再次同步或手动生成。
令牌失效后需在这里更新，密钥和令牌均不包含在项目导出文件内。

知识库状态和索引接口分别为 `GET /api/v1/knowledge?project_id=...` 和
`POST /api/v1/knowledge/index`（JSON：`project_id`、`payload_id`），均需管理员认证。
不使用知识库时，普通文字回复不依赖向量模型。

首次使用从 `.env` 读取 AI 默认值；在后台保存后，数据库配置优先于 `OPENAI_*` 环境变量。
项目导入导出不包含 API 密钥和全局接口配置，请备份完整数据库以保留这些配置。

网页登录使用 HttpOnly、SameSite=Strict 的会话 Cookie，HTTPS 部署时启用 Secure。
会话有效期为 12 小时；退出、重启应用或修改 `.env` 中的管理员凭据会使会话失效。
命令行仍可用显式 Basic 认证调用受保护接口；浏览器不会再弹出原生认证窗口。
未配置 `ADMIN_PASSWORD` 时，管理接口保持关闭。

使用反向代理时，`PUBLIC_URL` 必须与浏览器访问的地址一致，用于同源校验。
只有在代理覆盖 `X-Real-IP` 且应用端口仅对该代理开放时，才设置 `TRUST_PROXY=true`，
否则登录限流按连接来源统计。不要将应用端口直接暴露到公网。

### 开发与验证

```sh
bun install --frozen-lockfile
bun run typecheck
bun test
```

管理后台源码在 `frontend/`，开发时把 `/api` 代理到本地后端：

```sh
cd frontend
bun install --frozen-lockfile
CRISPAI_API=http://127.0.0.1:3000 bun run dev   # 打开 http://localhost:5173/login
bun run build                                   # 产物写入 frontend/dist，后端直接托管
```

Docker 镜像在构建阶段自动编译前端。不用 Docker 时，先构建 `frontend/dist` 再启动后端，
也可以用 `CONSOLE_DIR` 指向其他构建目录。

### 准备 Crisp 插件

这一步需要你自己在 Crisp 那边完成：

1. 在 <https://marketplace.crisp.chat> 创建一个私有插件
2. 申请需要的 scopes：会话消息的读写、会话 meta / 浏览页面的读取
3. Web Hooks 地址填 `https://你的域名/crisp`，订阅 `message:send`、`message:received`、`message:updated`
4. 把插件的 Token Identifier / Key、Web Hooks 签名密钥、URN 填进 `.env`，重启服务
5. **把插件安装到你的 Crisp 站点**：在 Marketplace 的插件页面里安装
6. 在管理后台创建项目，把该站点的 Website ID 填到「基础设置」里并启用项目

没安装插件的站点不会向 `/crisp` 推送任何消息，项目看起来就是「启用了但没反应」，排查时先确认这一步。

### 接入 Chatwoot（可与 Crisp 同时使用）

Chatwoot 通过「机器人」（Agent Bot）接入，需要 Chatwoot 能通过公网 HTTPS 访问 CrispAI：
Chatwoot 默认不向内网地址发送 Webhook。

1. 在 Chatwoot「设置 → 机器人」新建机器人。机器人的名称和头像就是访客看到的客服身份，
   项目里的「回复名称」「回复头像」只对 Crisp 生效
2. Webhook URL 填项目「基础设置 → Chatwoot」里显示的 `https://你的域名/chatwoot/<项目 ID>`
3. 把机器人详情里的 Access Token 和 Webhook Secret、Chatwoot 地址填到同一处，开启并保存；
   收件箱 ID 可选，填写后只处理该收件箱
4. 在收件箱「设置 → 机器人配置」里选中这个机器人

连上机器人后，新会话先是「待处理」状态，由 CrispAI 接待，访客消息照常转发到 Telegram 话题
（话题名以 `[Chatwoot]` 开头，信息卡里有打开该会话的链接）。触发「关闭智能回复」时，会话会转成「开放」，
进入客服列表；客服在 Chatwoot 或 Telegram 回复后，AI 按「人工接管后恢复自动回复」的时间暂停。
Webhook 带签名校验；项目或 Chatwoot 接入停用时返回 503，Chatwoot 会把待处理会话直接转给人工。

欢迎语在访客打开聊天窗口时发送，每位访客每小时最多一次；从没发过消息的访客会先新建一个会话。
请关闭 Chatwoot 收件箱自带的问候语，免得发两遍。
Chatwoot 会话的辱骂冷却单独计算，不与 Crisp 共享。机器人令牌和 Webhook 密钥只保存在服务器，不包含在项目导出文件内。

### 准备 Telegram

1. 找 @BotFather 创建机器人，token 填进 `.env`
2. 建一个开启了「话题」的群，把机器人拉进去并设为管理员（需要管理话题的权限）
3. 在群里发 `/ping`，机器人会回复群组 ID，填到项目的「基础设置」里

Webhook 由服务启动时自动注册到 `PUBLIC_URL/telegram`，并带 secret 校验。

### 欢迎语

在你的网站上，Crisp 脚本之后加一行（项目「基础设置」里有现成的可以复制）：

```html
<script type="text/javascript" src="https://你的域名/intro.js"></script>
```

### 网页客服的 emoji 与链接排版

AI 回复会补齐中文旁边的 Markdown 间距，并将裸网址转换为明确的链接；
代码块、已有链接的地址和图片内容保持原样。排版提示会要求模型使用简短的链接名称，
并把 emoji 放在说明文字旁边，避免独立表情被聊天窗口放大。
Telegram 转发只转换独立的文字表情，不会再将 `https://` 中的 `:/` 误改成 emoji。

如果宿主网站使用 Twemoji 处理全页文字，还需在**嵌入客服的网站**加载
[`integrations/crisp-widget.css`](integrations/crisp-widget.css)：
将它复制到网站静态资源目录，再添加相应的样式链接，例如：

```html
<link rel="stylesheet" href="/custom/crisp-widget.css">
```

该样式仅限制 `twemoji-emoji` 图片的大小，并允许客服链接在气泡内换行；
普通截图和头像不受尺寸规则影响。仅更新 CrispAI 容器不会自动修改独立的网站前端。
样式可影响已有消息的显示；回复内容的格式整理只对更新后的新 AI 回复生效。

## 日常操作

```bash
# 改了 .env：重新执行 up，compose 会用新配置重建 app 容器（数据库和 Redis 不受影响）
docker compose up -d

# 更新版本：拉代码后带 --build 重新构建镜像
git pull
docker compose up -d --build

# 看日志
docker compose logs -f app

# 备份数据库
docker compose exec postgres pg_dump -U crispai crispai > backup.sql
```

注意：

- `docker compose restart` **不会**重新读取 `.env`，改了配置要用 `up -d`
- `POSTGRES_PASSWORD` 只在数据库首次初始化时生效，之后改 `.env` 里的值不会改掉数据库的实际密码，
  反而会让 app 连不上。确实要换密码，先在数据库里执行 `ALTER USER crispai PASSWORD '新密码';` 再改 `.env`
- `docker compose down` 只删容器，数据还在；`docker compose down -v` 会连数据卷一起删掉，**数据库和图片都会丢**

### 网站实时查询（V2Board）

在项目「智能回复」标签的「网站实时查询」中填写：HTTPS API 基址（以 `/api/v1` 结尾）、官网地址和普通专用账号的 Authorization 令牌，然后保存、测试并开启。它与文档同步独立：教程继续按计划同步，套餐和公告等由支持 OpenAI 工具调用的对话模型按需实时查询。无需向量模型。

固定工具 `get_site_information` 仅接受 `plans`、`notices`、`payments`、`site_config` 四个主题。读取的接口为 `/user/plan/fetch`、`/user/notice/fetch?current=1&pageSize=10`、`/user/order/getPaymentMethod`、`/user/comm/config` 和 `/guest/comm/config`。套餐金额和固定手续费从分换算为主货币单位；缺失价格不等于免费。只返回允许的字段，不返回支付密钥、账号余额或订阅凭据。

每条消息最多两轮工具调用、四次查询请求；同一主题仅在当前消息内复用，下一条消息重新读取。工具输出使用 `tool` 角色，仅为低信任参考，不写入会话历史。失败时返回固定错误，不回显令牌或上游响应，也不把历史价格当实时结果。模型仍可能选错查询或误读资料，不能保证消除提示词注入；该集成不提供通用 HTTP、订单、节点、余额、订阅或写操作工具。

授权令牌保存在服务器的项目设置中，浏览器只读取“已保存”状态。空白保留已有令牌，更改 API 基址时必须重新填写。普通账号在 V2Board 本身仍可能有写权限，应专用并定期撤销不再使用的会话；本服务的限制来自固定路径与参数白名单。不要填写管理员令牌。管理接口 `GET/PUT /api/v1/site-api?project_id=...`、`POST /api/v1/site-api/test?project_id=...` 受后台认证保护。测试按钮只测试数据接口，不替代模型工具调用能力测试。


管理界面使用带内容版本的资源路径（`/console-assets/<内容摘要>/...`），模块以相对地址导入同版本依赖，避免 CDN 缓存导致新表单配旧脚本。网站查询配置独立于模型列表加载；按钮显示保存/测试进度，读取失败可重新读取，失败不会清空输入。令牌保存后不回显，服务器会返回“已保存”状态。未保存的修改会阻止测试旧配置并提醒保存。

### 三次警告、静默冷却与邮箱关联

在项目「AI配置 → 辱骂警告与静默冷却」开启。明确针对客服的人身辱骂/威胁才计次，普通投诉与引用不计次。第三次发送固定警告后，进入固定60分钟冷却；后续消息完全静默，不发送拒绝回答或其他自动文本，已生成但未发送的AI内容同样拦截。冷却中的新消息不调用模型，继续发消息不会延长冷却。期满下一条消息自动恢复并清零；人工暂停的会话不会被误重开。

冷却或人工暂停只限制自动回复，访客消息仍照常转发到Telegram供人工接待；冷却中的同邮箱新窗口也会创建对应话题。新话题的AI控制按钮显示实际冷却状态。

从Crisp服务端会话元数据读取email，规范化大小写/首尾空格后，按同一站点内同邮箱共享计数和冷却。摘要使用HMAC-SHA256及服务器ABUSE_IDENTITY_KEY（未配置时使用现有ADMIN_PASSWORD），黑名单不保存明文邮箱。不要从聊天正文、昵称或自定义Email字段推断身份。拿不到邮箱时退回会话身份，无法识别匿名新会话。此HMAC仅用于本地摘要，**不是**Crisp SDK的身份签名：当前前端没有邮箱签名验证，改变邮箱或匿名聊天仍可能绕过关联；对抗这类情况需另外接入签名身份验证。

所有自动发送出口（文本、关键词、选项、欢迎语和输入状态）统一检查冷却，并在模型生成后、实际发送前再次检查。共享身份锁使警告计数与发送决策不会跨窗口竞争。仅刚刚创建的第三次固定警告可在进入冷却时发送一次；历史待发送警告不会在冷却期间反复出现。网络断开时无法保证外部消息恰好送达一次，但同一指纹不重复计次。人工Telegram回复不受自动回复冷却限制；“解除冷却并开启AI（清零）”可提前恢复同邮箱身份。

黑名单按Crisp站点隔离；冷却不是用户账户封禁，不修改Crisp Inbox的resolved状态。现有永久结束记录迁移为从原第三次警告时间起计算的一小时冷却。图片/语音不做辱骂分类，分类器失败或JSON不合法不处罚访客，每条接待中的文字消息可能额外产生一次模型调用。

配置接口保持`GET/PUT /api/v1/settings/abuse?project_id=...`，只接受enabled开关。应用会话及摘要状态保存在PostgreSQL，刷新或应用重启不会重置仍有效的冷却。
